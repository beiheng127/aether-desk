# 实战工作流：给 Aether Desk 做「会话导出 JSON」

> 一个可演示、可写进简历的 Agent 场景：从需求 → 检索知识 → 方案对比 → 生成待办（HITL）→ 沉淀笔记。

---

## 场景背景

**产品需求：** 用户想把某次 Agent 会话（消息 + 工具记录 + 制品）导出为 JSON，用于备份、迁移或面试演示回放。

**为什么适合 Aether Desk：**
- 知识库里已有《会话导出 JSON 功能需求》等笔记
- 需要 **RAG 检索** 历史方案，而不是模型瞎编
- 需要 **表格对比** 两种技术路线
- 需要 **HITL 待办** 把开发任务落地，而不是 Agent 悄悄改代码

---

## 期望 Agent 行为（逐步）

| 步骤 | Agent 做什么 | 你在 UI 上看到什么 |
|------|----------------|-------------------|
| 1. 规划 | 理解要做「会话导出」 | phase → 规划 |
| 2. 检索 | 调用 `search_notes`，query 含 export/session/JSON | 工具时间线 #1 `search_notes`，右侧引用卡 |
| 3. 回答 | 总结需求 + 实现步骤，带 `[1][2]` 引用 | 对话区 Markdown（表格/列表已渲染），气泡可滚动 |
| 4. 对比 | 调用 `summarize_diff` 对比方案 A/B | 右侧 **表格卡** 制品 |
| 5. 待办 | 调用 `create_task_card` 列开发任务 | 工具「待确认」→ 你点 **批准** |
| 6. 可选 | `save_note` 沉淀结论 | 知识库多一条笔记 |

## 两种导出方案（知识库摘要）

| 维度 | 方案 A：客户端导出 | 方案 B：服务端导出 API |
|------|-------------------|------------------------|
| 实现 | 复用 `GET /api/sessions/:id` 快照，前端 `Blob` 下载 | 新增 `/api/sessions/:id/export` 流式写文件 |
| 优点 | 改动小、上线快 | 适合超大会话、可审计 |
| 缺点 | 大会话占内存 | 需新增路由与测试 |
| 安全 | 读操作，无需 HITL | 读操作，记录导出日志更佳 |

（完整表述在知识库笔记《会话导出 JSON 功能需求》）

## 建议拆分的开发待办（HITL 示例）

1. **API**：确认 `GET /api/sessions/:id` 返回字段是否满足导出  
2. **UI**：会话列表增加「导出 JSON」按钮 + 下载文件名  
3. **体验**：导出过程 loading；失败 toast  
4. **文档**：在 `docs/` 补充导出格式说明  
5. **可选**：大会话走方案 B 的服务端 export  

Agent 生成的待办会在 **制品区** 以 checkbox 展示；你批准后才算「确认执行计划」。

## 演示话术（面试 90 秒）

> 我用 Aether Desk 走了一个真实需求工作流：要做会话导出。Agent 不是直接写代码，而是先 hybrid 检索我自己的需求笔记和架构约束，再给出步骤和引用。方案对比用 `summarize_diff` 落到表格制品，开发任务用 `create_task_card` 生成，我必须点批准才生效——这是 HITL。整个链路会话、工具、制品都落在 SQLite，可回放。这体现的是 **Agent 前端 + 服务端编排 + RAG + 可观测 + 安全写操作**，不是聊天 Demo。
